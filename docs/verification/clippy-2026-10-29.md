# Clippy lint selection, 2026-10-29

Baseline: `938cb8b`. Tool: Clippy 0.1.99 (`58cf8f9c35`, 2026-10-13).

The exploratory runs force-enabled `clippy::all`, `clippy::pedantic`,
`clippy::nursery`, `clippy::restriction`, and `clippy::cargo`, including locally
allowed lints. The root package was checked with all targets on ARM macOS
(default and all features), all targets on x86 Linux (all features), and the
portable Wasm library (default features). The separate resource-profiler and
fuzz packages were checked with all targets and features. Archived benchmark
fixture packages under `docs/benchmarks` were excluded.

These runs reported 122 distinct lint kinds. The decisions below cover every
reported kind. Counts of individual diagnostics are not meaningful: shared
source files appear in multiple test/benchmark crates and configurations.
This is lint triage, not a proof of every arithmetic or pointer invariant.

The permanent policy selects individual lints, following the
[Clippy guidance](https://doc.rust-lang.org/clippy/lints.html) for restriction
and nursery lints. It does not permanently enable either entire group.

## Enabled

All twelve lints below are enabled in the root manifest. The independent
resource-profiler manifest enables `allow_attributes_without_reason`,
`assertions_on_result_states`, and `undocumented_unsafe_blocks`; the fuzz
manifest enables `allow_attributes_without_reason`.

| Lint | Useful result |
| --- | --- |
| `allow_attributes_without_reason` | Record why shared helpers or direct argument passing need an exception. |
| `assertions_on_result_states` | Print the unexpected success or error value on test failure. |
| `chunks_exact_to_as_chunks` | Give the fixed-size cache-eviction loop array chunks; retain its remainder behavior. |
| `doc_markdown` | Render identifiers and source paths as code. |
| `ignore_without_reason` | Explain why the maximum-transform test runs separately. |
| `manual_assert_eq` | Include both values when equality assertions fail. |
| `missing_errors_doc` | Document invalid characters, insufficient output, and exact-length errors. |
| `must_use_candidate` | Warn when capacity, scratch-size, or memory-accounting results are discarded. |
| `or_fun_call` | Avoid allocating unused default vectors in benchmark setup. |
| `precedence_bits` | Make limb assembly and bit-test precedence explicit. |
| `should_panic_without_expect` | Check the intended assertion; zero-scale expectations differ in debug and release. |
| `undocumented_unsafe_blocks` | Put CPU-feature, memory-range, and allocator explanations beside unsafe operations. |

Existing default warnings were also resolved: `type_complexity` now uses named
benchmark types, and `vec_init_then_push` uses a single conditional vector
initializer. `too_many_arguments` retains its existing narrow allowance with
a reason. `unnecessary_cast` retains the Malachite allowance: its limb width
can change through dependency feature unification.

## Rejected after inspection

| Lints | Reason |
| --- | --- |
| `arithmetic_side_effects`, `as_conversions`, `cast_lossless`, `cast_possible_truncation`, `cast_possible_wrap`, `cast_precision_loss`, `cast_sign_loss` | Numeric kernels deliberately widen, narrow, and extract limbs. Blanket rewrites do not establish their range invariants. Timing/resource reports deliberately convert sizes to floating point. |
| `integer_division`, `integer_division_remainder_used`, `modulo_arithmetic`, `float_arithmetic` | Exact quotient/remainder operations and measurement arithmetic are required here. |
| `cast_ptr_alignment` | The flagged matrix pointers are passed to unaligned SIMD loads/stores, not dereferenced as aligned vector references. |
| `big_endian_bytes`, `little_endian_bytes`, `host_endian_bytes` | Explicit byte order is part of radix conversion; native-endian adapters stay inside local kernels. |
| `indexing_slicing`, `string_slice` | Kernel dimensions and ASCII conversion boundaries are intentional. A blanket indexing ban would obscure these contracts. |
| `missing_asserts_for_indexing` | Adding assertions for optimization needs measurement and a specific bounds-check problem; it is not a mechanical correctness fix. |
| `large_stack_arrays` | The aligned matrix scratch frame is deliberate, including allocation-free paths. Heap allocation would change that contract. |
| `inline_always`, `missing_inline_in_public_items` | Kernel inlining and out-of-line dispatch depend on measured code size and performance. |
| `cognitive_complexity`, `too_many_lines`, `single_call_fn` | Splitting the IFMA kernel or measurement driver solely to satisfy thresholds has no demonstrated benefit. |
| `missing_const_for_fn` | Expanding const APIs and changing helper declarations is not needed for these findings. |
| `missing_panics_doc`, `unwrap_in_result`, `unwrap_used`, `expect_used` | Findings include impossible fixed-length/ASCII failures, internal invariants, and test oracles. Actual tuning preconditions already have documentation; adding unreachable-panic sections would misstate valid input behavior. |
| `panic`, `panic_in_result_fn`, `unreachable` | Internal assertions, unsupported tuning values, and oracle failures must remain visible. They are not recoverable conversion errors. |
| `multiple_unsafe_ops_per_block`, `unnecessary_safety_comment` | Keep related operations under one documented invariant, and preserve safety contracts on private unsafe functions. |
| `maybe_infinite_iter` | The primality test stops when d*d exceeds a fixed prime below 2^30; it cannot reach multiplication overflow. |
| `float_cmp` | The benchmark highlights the exact minimum chosen from the same floating-point values, so exact equality is intended. |
| `unnecessary_struct_initialization` | Without caching, an initializer contains only a struct update; with caching, it sets `force_owned`. The conditional construction is intentional. |
| `map_err_ignore` | Competitor adapters deliberately translate their error types into this crate's comparison interface. |
| `wildcard_enum_match_arm` | Oracle matches deliberately panic on any unsupported dependency error, including future variants. |
| `exhaustive_enums`, `exhaustive_structs` | Adding non-exhaustive API restrictions would change callers; no such API change is needed. |
| `missing_trait_methods` | Default multiplier/allocator methods are intentional; restating defaults adds no behavior. |
| `error_impl_error` | Implementing the standard error trait is required for the public error types. |
| `print_stdout`, `print_stderr`, `use_debug` | Benchmark results and test diagnostics deliberately use output and Debug formatting. |
| `non_ascii_literal` | Invalid UTF-8/Base58 test fixtures deliberately include non-ASCII characters. |
| `blanket_clippy_restriction_lints` | Expected during exploratory force-enablement; the permanent policy selects individual lints. |
| `allow_attributes` | Shared support code needs allowances across different harnesses; expectations would become unfulfilled in some configurations. Require reasons instead. |
| `borrow_as_ptr` | The process-clock FFI intentionally borrows a live local timespec; an explicit raw borrow adds no correctness benefit at this call. |
| `assert_is_empty`, `missing_assert_message` | Existing tests use ordinary assertions and often already provide surrounding context. A blanket message/empty-assert rewrite adds little. |
| `absolute_paths`, `pub_use`, `redundant_pub_crate`, `pub_with_shorthand`, `field_scoped_visibility_modifiers`, `definition_in_module_root` | Keep explicit internal visibility and the existing public/internal re-export boundaries. |
| `mod_module_files`, `self_named_module_files`, `inline_modules`, `multiple_inherent_impl`, `tests_outside_test_module` | Preserve the existing module and test layout; two filename conventions even conflict. |
| `arbitrary_source_item_ordering`, `items_after_statements` | Preserve explanatory source order and constants near the operations that use them. |
| `many_single_char_names`, `min_ident_chars`, `single_char_lifetime_names`, `module_name_repetitions`, `renamed_function_params` | Mathematical names and trait implementation names are clear in their existing context. |
| `default_numeric_fallback`, `decimal_literal_representation`, `unreadable_literal`, `unseparated_literal_suffix` | Numeric spelling and inferred types do not reveal a defect in these findings. |
| `implicit_return`, `question_mark_used`, `impl_trait_in_params`, `inline_trait_bounds`, `pattern_type_mismatch`, `ref_patterns`, `rest_pattern_accessible_field`, `unnecessary_rest_pattern`, `ignored_unit_patterns` | Preserve ordinary Rust return, error propagation, signature, and pattern conventions. |
| `shadow_reuse`, `shadow_same`, `shadow_unrelated` | Successive values and narrowed representations deliberately reuse local names. |
| `missing_docs_in_private_items`, `too_long_first_doc_paragraph`, `doc_link_code` | Keep private commentary and API prose proportional; the adjacent code links are intentional function notation. |
| `deref_by_slicing`, `explicit_iter_loop`, `map_with_unused_argument_over_ranges`, `match_bool`, `match_same_arms`, `option_if_let_else`, `range_plus_one` | Equivalent spelling changes do not improve the inspected algorithms or tests enough to justify a permanent rule. |
| `redundant_closure_for_method_calls`, `needless_pass_by_value`, `std_instead_of_core`, `string_add`, `unused_trait_names`, `use_self`, `wildcard_imports` | These suggestions mostly change local spelling or test imports; some make short code harder to read. |
| `semicolon_if_nothing_returned`, `semicolon_inside_block`, `semicolon_outside_block` | Existing statement spelling is clear; the latter two preferences conflict. |

## Verification scope

The selected policy is checked with warnings denied for all eight existing
feature configurations on ARM macOS and cross-compiled x86 Linux. Portable
checks cover Wasm, ARM Linux, Thumb bare metal, and x86 bare metal. The declared
Rust 1.95 minimum is checked with default and all features. The profiler and
fuzz packages are checked separately, with default and all features.

CI now checks root tests, examples, and benchmarks as well as the library;
adds native ARM Clippy checks and portable library Clippy checks; and lints
the independent profiler/fuzz manifests.

Local tests cover cached/compact debug code, uncached debug code, release unit
tests (including the different zero-scale panic), profiler tests/self-checks,
and documentation. Cross-compiled x86 checks do not execute SIMD instructions.
No performance benchmark or full sanitizer/formal-verification campaign is
claimed for this lint-only change.
